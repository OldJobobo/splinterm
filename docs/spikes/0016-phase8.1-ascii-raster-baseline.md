# Spike 0016: Phase 8.1 printable-ASCII raster baseline

- **Status:** Baseline recorded; parity fails and remains release-blocking
- **Reference:** Foot 1.27.0 at `3c5b584b0eafa772eb4376fb6eaf6643399e190e`
- **Scope:** U+0020 through U+007E at 22 px, grayscale/no-subpixel rasterization

## Purpose

Phase 8 integration showed visible font-rendering differences from Foot. This
spike replaces the earlier representative-glyph evidence with a strict,
cell-identified comparison of every printable ASCII character. It records the
current divergence before production metrics or placement are changed.

## Reproduction

```bash
tools/foot-oracle/run-ascii-comparison.sh /tmp/splinterm-ascii-comparison
```

The command writes:

- `fcft-reference.jsonl`: pinned fcft metrics and tightly packed alpha masks;
- `swash-actual.jsonl`: Splinterm's provisional Swash metrics and masks;
- `freetype-actual.jsonl`: the bounded production-candidate bridge output;
- `swash-diff/` and `freetype-diff/`: structured per-glyph results and PGM
  alpha-difference heatmaps.

A nonzero exit is expected until parity is achieved. The comparator aligns by
stable label and declared glyph geometry; it never translates masks to improve
the score.

## Reference-host result

The initial Phase 8.1 run compared 95 reference and 95 actual ASCII records:

- **0 passed; 95 failed** the combined geometry-and-mask gate;
- all 95 report a one-pixel font-height mismatch (fcft 29 px, current Swash
  metric calculation 30 px);
- 3 differ in placement: `.`, `<`, and `>`;
- 6 differ in raster image dimensions: `"`, `'`, `+`, `.`, `<`, and `>`;
- 8 differ in nonzero ink bounds: `"`, `'`, `(`, `)`, `+`, `.`, `<`, and `>`;
- only 8 records have zero alpha mismatch under the strict raw-byte comparison.

The matching ascent, descent, and integer advance do not make the final raster
Foot-equivalent. In particular, current `cell_metrics()` computes height from
ceiled Swash floating metrics while fcft exposes a 29 px height for this exact
font/configuration.

## First metric correction

`CellMetrics` now rounds the complete scaled line extent once instead of ceiling
it. This changes the production default cell from 13×30 to 13×29 and matches
the pinned fcft height without a character-specific adjustment. The pure metric
test fixes the observed 13.2 px advance and fractional vertical extents at a
13×29 cell with baseline 23.

After that correction, the same command reports **8 passed and 87 failed**.
There are no longer global font-height differences. The remaining classified
geometry differences are the same 3 placements, 6 image dimensions, and 8 ink
bounds; 87 glyphs still differ in alpha bytes. This separates the corrected
cell geometry from the unresolved rasterizer behavior.

## Rasterizer and style decision

The pinned fcft path uses fontconfig's slight hinting as FreeType light-target
loading followed by normal grayscale rendering. Swash 0.2.10 uses Skrifa's
fixed smooth horizontal-LCD hinting configuration and Zeno's alpha scan
converter; its public scaler does not expose a FreeType-light-equivalent mode.
Exact cross-engine bytes are therefore not a supportable assumption.

Do not add per-character offsets or loosen the comparator. The dedicated
`splinterm-freetype` bridge uses `freetype-rs` without first-party unsafe code,
loads with FreeType's light target, renders normal grayscale, validates bitmap
geometry/pitch, and returns bounded owned alpha data. On the pinned host its
isolated U+0020–U+007E comparison passes **95/95** with zero geometry or alpha
mismatches.

The bridge is now integrated into the production scale/face-keyed snapshot
glyph cache for regular, bold, italic, bold-italic, and CJK grayscale faces.
Color emoji remains on Swash's color-capable path. A second exporter invokes
the real production cache and also passes **95/95** for default printable ASCII
with zero geometry or alpha mismatches.

Production snapshot preparation now selects distinct regular, bold, italic, and
bold-italic primary faces from terminal cell attributes. Their face index is
part of the glyph-cache key, and an integration test proves four styled `A`
cells produce four distinct face/cache identities. Synthetic style and styled
fallback behavior remain unresolved parity cases.

The oracle schema now includes fcft underline/strike position and thickness.
Production `CellMetrics` matches the pinned values (underline −3/1 px,
strike 7/1 px at 22 px), and `SnapshotFrame` renders single underline and
strikethrough through both full and dirty-row paths with byte-identical output.
Protocol v10 replaces the boolean underline with explicit none, single, double,
curly, dotted, and dashed styles and carries an independent SGR 58/59 underline
color. The terminal parser implements `4:0` through `4:5`, `21` as Foot's double
underline, `24` reset, and underline color set/reset. Full and dirty-row paths
render bounded distinct patterns and preserve custom underline color separately
from foreground-colored strikeout.

The richer renderer-independent state increases `Attributes` from 8 to 20 bytes
and `Cell` from 12 to 24 bytes. The memory-layout baseline records this deliberate
Phase 8.1 cost; the performance gate must measure its grid/history impact before
the phase closes.
